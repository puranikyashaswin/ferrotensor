Ferrotensor

A pure-Rust GPU ML framework: tensors, autograd, nn and LoRA fine-tuning on Metal, Vulkan or DX12 through hand-written WGSL kernels. No CUDA, no C++ toolchain.

$ pip install ferrotensor

Python 3.10+. Wheels for macOS arm64 and Linux x86_64; no NumPy needed.

$ cargo add ferrotensor

The tensor API in your project. Rust 1.88+; on macOS nothing else to install.

$ cargo install ferrotensor-cli

The ferrotensor command: LoRA train, eval and generate.

03 · Architecture

Every layer, down to the shader

Two stacks in one workspace. The ferrotensor crate is the PyTorch-style tensor API with its own kernels and a CPU device. The LLM stack has purpose-built kernels for Llama-style models and the LoRA command-line tool. Both reach the GPU through wgpu.

04 · Context

Compared with candle, burn and tch-rs

These are good projects; Ferrotensor is not trying to replace them. The honest picture, from the README:

Ferrotensor candle burn tch-rs
What it is Small pure-Rust framework on wgpu Minimalist Rust ML framework from Hugging Face Full Rust deep-learning framework with swappable backends Rust bindings to libtorch (PyTorch's C++ library)
GPU story wgpu only: Metal, Vulkan, DX12 CUDA and Metal, plus CPU wgpu, CUDA, Metal, CPU and others through backends Whatever libtorch supports, notably CUDA
Needs a C++/CUDA toolchain No For CUDA builds Depends on backend Yes, libtorch
Maturity Young, pre-1.0, one maintainer Widely used, many reference model implementations Widely used, training-focused, large API Mature, full PyTorch op coverage
Model zoo / ecosystem Tiny Large Growing The whole PyTorch ecosystem via TorchScript/weights

Choose candle for inference of popular models, burn for a mature all-Rust training framework, tch-rs when you need exact PyTorch semantics and CUDA.

Choose Ferrotensor to learn how the stack works end to end, when you want a dependency-light wgpu-only codebase you can read and modify, or to experiment on a consumer GPU without installing CUDA. It does not match their op coverage, model support or hardening, and it has not been benchmarked against them.

05 · Limits

What it can't do yet

Small-scale by design, and young. Before you pick it up, know this:

  • f32 only. No f16 or bf16 tensors in the tensor API yet.
  • One GPU. No multi-GPU or distributed training; the CLI's --world-size flag is a prototype.
  • Small models. LoRA fine-tuning is experimental and aimed at small Llama-style models; the measured run is SmolLM2-135M. Released LFM2 checkpoints are not supported.
  • Tiny workloads are faster on the CPU. A chain of 100 tiny ops still takes about 18× as long on the GPU as on the CPU; op fusion is the next step.
  • Not every op. No convolutions, sort, top-k or cumsum in the tensor API.
  • Far from peak. Matmul reaches about 17% of the M2's FP32 peak; WGSL does not expose the matrix instructions that close that gap.
  • Pre-1.0. The API can still change, and Python wheels exist for macOS arm64 and Linux x86_64 only (other platforms build from source).

06 · FAQ

Questions, answered plainly

What is Ferrotensor?

Ferrotensor is a pure-Rust GPU machine-learning framework. It runs tensors, autograd, neural-network layers and LoRA fine-tuning on Apple Silicon through Metal, or on Vulkan and DX12 GPUs on Linux and Windows, using wgpu and hand-written WGSL compute kernels. It has Python bindings and is licensed MIT OR Apache-2.0.

Does Ferrotensor need CUDA or an NVIDIA GPU?

No. Ferrotensor reaches the GPU through wgpu, so it runs on Metal, Vulkan or DX12, and there is no CUDA, cuDNN or libtorch to install. A CUDA backend is not planned. Without a GPU, the same code runs on the CPU device.

Can I fine-tune a model on a MacBook?

Yes, a small one. On a MacBook Air with an Apple M2 and 8 GB of memory, LoRA fine-tuning of SmolLM2-135M on 2,000 Alpaca examples took the held-out loss from 2.43 to 1.65 in 250 steps, at 8.8 s per step and 3.3 GB peak memory. The LoRA path is experimental and aimed at small Llama-style models; the LoRA walkthrough lists every command.

How do I install Ferrotensor in Python or Rust?

For Python 3.10 or newer, run pip install ferrotensor; wheels are built for macOS arm64 and Linux x86_64. In a Rust 1.88+ project, run cargo add ferrotensor. For the LoRA command-line tool, run cargo install ferrotensor-cli. The installation guide has the details.

How does Ferrotensor compare with candle and burn?

candle is a minimalist Rust framework from Hugging Face, a good choice for inference of popular models; burn is a mature all-Rust training framework with swappable backends. Ferrotensor is smaller and younger: it targets wgpu only, needs no C++ or CUDA toolchain, and is written to be read and modified end to end. It does not match their op coverage, model support or hardening, and it has not been benchmarked against them.

What are Ferrotensor’s limits?

It is pre-1.0 and f32 only, runs on a single GPU, and has no convolutions, sort or top-k in the tensor API yet. Chains of tiny ops are still faster on the CPU. LoRA fine-tuning is experimental and tested on small Llama-style models. The limits section above has the details.
